# Toolgen 0.17 – Retrace

Spurgewehr umbenannt: `scout_rifle` → `trace_rifle`. Entscheidung des Nutzers vom 19.10.2026 (cubeescape-design `claude/docs/ENTSCHEIDUNGEN.md`,
hier [ENTSCHEIDUNGEN](../ENTSCHEIDUNGEN.md)): Beim Abgleich mit dem Destiny-Waffensortiment (DS 0.10/0.10.1) zeigte sich, dass die ID das
Spurgewehr (Destiny Trace Rifle) bezeichnete, während ein echtes Scout-Gewehr als eigener Designtyp entsteht (Blatt KG11, `toolgen_id` null).
Reihenfolge Toolgen → Cube Escape → cubeescape-design. Basis: `main` e84f9bf (0.16.0 Finegrain). Technik: [TECHNIK](../TECHNIK.md) › Waffen 1–9 ›
Umbenennen; Einbau: [UNITY_EINBAU](../UNITY_EINBAU.md) › Umbenannte Werkzeuge.

## 0.17.1 – Retrace (19.10.2026)

### Befunde

- **Codex-Prüfung (`gpt-6-luna`, medium, nur lesend, 558 Diff-Zeilen):** zwei Befunde. (1) Der erste Entwurf baute `renamed_from` in
  `build_contract` aus dem schon umbenannten Varianten-Eintrag: im Ego-Vertrag stand `CubeEscape_ScoutRifle` → `CubeEscape_TraceRifle_FPS`,
  im Roboter-Vertrag → `CubeEscape_TraceRifle_Robot` (an der quick-Ausgabe bestätigt). Behoben: `export()` berechnet den Block aus dem
  Katalogeintrag, bevor die Variante den Asset-Namen ändert; Test `test_contract_block_uses_the_catalogue_names`. (2) Formulierung der
  Mindestversion (Toolgen statt Cube Escape als Abnehmer) richtiggestellt.
- **Alte Pakete in der Ausgabe:** Ein vorhandener Ausgabeordner behält nach dem Umbenennen `scout_rifle/` (die Pipeline löscht keine fremden
  Pakete; beobachtet in `output/_quick` dieses Worktrees, Stand 18.10.). `catalog.json` nennt es nicht; `generate_tools.py` warnt jetzt
  (`foreign_packages`, nichts wird gelöscht). Abnehmer kopieren nur, was `catalog.json` nennt.
